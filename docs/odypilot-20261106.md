# OdyPilot update: November 6, 2026

This update adds three Odyssey improvements to `pselden/openpilot:sp-ody`.
Base application: `6f1dff70b74218ce807956ca9c835b8274c3c987`.
Base vehicle code: `2bde811b755d9635a9665f5398a56c16c1146042`.

## Steering learning

Port Patrick's [`c4bd45462`](https://github.com/prehkopf/openpilot/commit/c4bd45462e055fe6aee15f5a3cd1aaea0916ed6b),
adapted upstream from brikowski `ef598cd282`.
Self-Tune collects and fits samples at the original 2560-count physical scale,
then publishes the result in our 3840-count normalization. Existing Odyssey fits
from the old normalization are rejected; learning starts from the existing
offline tune. Steering range, tune, slew, and safety limits are preserved.

## Stable longitudinal response

Port the ten brikowski opendbc changes after `24057b269` through
[`c91503afe`](https://github.com/brikowski/opendbc/commit/c91503afe54b51b018770bf5dd805bd18413cab1),
the vehicle-code pin in brikowski's November 2 stable application release:

- `49d8c1d8d`: withdraw warmup gas correction in proportion to reverse error.
- `0573073eb`: retain qualified coast through small response changes.
- `27628fdce`: use consistent uphill grade compensation across zero demand.
- `554d5ee23`: retain learned gas reductions through coast.
- `4deda8a84`: withdraw added gas during sustained excess acceleration.
- `a741ce343`: share one buffer for uninterrupted coast observations.
- `19d433ef1`: retain completed coast calibration between observations.
- `852c47a9b`: preserve that calibration through idle stop, with fresh-input guards.
- `a8d758d88`: isolate Odyssey gas calibration per controller.
- `c91503afe`: use the existing 5 m/s domain boundary for passive-response handoffs.

The port retains sunnypilot's CarParamsSP/CarControlSP interfaces, Odyssey's
gas-map floor, van-load presets, and cluster HUD changes. Gas calibration now
lives on the Odyssey controller instance instead of changing shared Honda class
state. New and updated upstream behavior tests are adapted to these interfaces;
native ECON transitions remain outside this port.

## Lead departure chime

Port Patrick's [`c21fc101c`](https://github.com/prehkopf/openpilot/commit/c21fc101c3b4e75c31ba9bd91f56f3e3d3967d75).
The lead must move 3 metres for 0.5 seconds before the chime. Once armed, the
observer stays armed while that lead moves beyond the initial 8-metre gate.
This reduces alerts from distance jitter and small creeps, at the cost of a
later departure notification. The existing alert preference is retained.

## Validation

- Honda vehicle/HUD and safety suites: 1,292 passed, 611 skipped, 2,424 subtests passed.
- Steering learner, existing torque learner, departure chime, and turn-intent
  tests: 47 passed. Chime tests use real messages and isolated stored preferences.
- Five shared response helpers/classes match the stable source after the
  existing Odyssey gas-floor substitution. Van-load feedforward remains local.
- Changed Python lint, shell syntax, and whitespace checks pass.

The full Linux build, recorded-drive replays, and on-device timing and driving
were not run. Optional cruise/launch regression tests could not collect because
this checkout lacks the generated native MPC solver; their implementation is
unchanged. macOS tests used the installed stable SDK because the default SDK
could not link with the installed linker.

Blendful, predictive Acceleration Boost, broader sunnypilot/comma updates,
Brikowski's later test-branch trials, and Patrick's calibration-limit changes
are not included. Runtime pins, settings profile, DEC, following defaults,
artwork, Dropbox archives, Panda, and AGNOS are unchanged. No device was updated.
