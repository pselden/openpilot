Odyssey RDM investigation

This branch changes offline diagnostics only. It is not a vehicle-control fix.

The existing replay script regenerated HUD messages and counted their RDM_OFF
bits. That demonstrates what the packer would generate; it does not establish
what Panda transmitted, whether the camera received a command, whether the
camera cleared RDM_PROBLEM, or whether the handsfree timer was suppressed.

The replacement reads actual Panda TX/rejection echoes and camera RX separately.
It also records successful radar-disable TX times. It never connects to hardware,
transmits CAN, changes Panda safety configuration, or clears ECU fault codes.

Run from the repository root, with pycapnp and zstandard installed:
  python tools/scripts/replay_odyssey_hud_rdm.py /path/to/rlog.zst
  python -m unittest tools.scripts.tests.test_replay_odyssey_hud_rdm

Times are seconds from the first CAN event in the supplied segment. This differs
from the old tool's carState-based replay window. Defaults are the non-CAN-FD
Odyssey alpha-long bus layout: TX bus 1, camera RX bus 2. An absent camera stream
is reported as not_observed, not success. fault_observed means the flag appeared
at least once within the selected window; it does not imply it stayed asserted.
The bit layout is the Honda DBC definition for legacy five-byte LKAS_HUD and
split LKAS_HUD_A/B. This is not a generic cross-platform CAN fault decoder.

Current evidence
The old and patched startup logs both raise camera RDM_PROBLEM approximately
200 ms after the radar-disable request transmits. The patched HUD changes
RDM_OFF on powertrain bus 1. Panda does not forward bus 1 to camera bus 2, and
the non-CAN-FD controller does not send the camera-side radar replacement stream
used for CAN-FD. Vehicle-side routing and camera ECU semantics remain unknown.
Camera messages already report RDM_OFF before their RDM_PROBLEM flag rises.

A stock-longitudinal comparison and camera ECU diagnostic trouble codes are
needed to distinguish loss of radar communication from failure to disable RDM.
The Odyssey firmware database identifies the forward camera request address as
0x18DAB5F1. That is a diagnostic lead, not authorization to change ECU state.
Do not assume a camera-side HUD copy will repair the fault, mask RDM_PROBLEM,
or weaken Panda safety checks to make a test pass.
